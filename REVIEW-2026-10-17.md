# M20 Character Builder — State of the App Review (2026-10-17)

Scope: live app code (`app/public/js/*`, `app/server/*`), extracted game data (`js/data.js`, `data/wonders.json`, `server/rotes-seed.json`), deployment, and the production SQLite database (read-only). Nothing was modified.

## Headline

The app is healthy and in real use: 331 users, 572 characters, 59 chronicles, 954 rotes, zero crashes in the container log over 30 days apart from 6 failed PDF exports. The server code is solid on the basics (parameterised SQL, bcrypt, session regeneration, admin guard, generic errors). The main risks are a handful of specific, cheap-to-fix bugs, one real authorisation hole, cross-user XSS in the sheet view, and the fact that the whole project lives outside version control with no tests.

Data splits cleanly into two tiers. `data.js` is hand-authored and clean (schema inconsistencies only). `rotes-seed.json` and `wonders.json` are raw PDF text and are dirty in ways users see: 71% of rote descriptions are truncated mid-sentence, and most wonder descriptions bleed into the next entry.

## 2. Database health (read-only snapshot)

- `integrity_check` ok, `foreign_key_check` clean. WAL ~4 MB is the normal autocheckpoint threshold, not a leak.
- Sessions prune correctly (0 expired of 79).
- Orphans: 6 characters with no user, 3 chronicles with no owner, 57 share tokens pointing at deleted characters, 99 password reset tokens never pruned, 143 approved `pending_edits` kept forever. Cause: `share_tokens`, `character_likes`, `password_reset_tokens`, `characters.user_id` have no FK constraints and admin user-delete only removes characters + user (`admin.js:364-373`).
- `data/template.pdf` is shipped but unused; the PDF is drawn from scratch with pdf-lib.

## 3. Frontend architecture and code quality

- 14,424-line `js/app.js`, vanilla JS, no build. Module-object singletons (`App`, `Auth`, `Grimoire`, `Chronicle`, `Sheet`, `Creator` ~5,600 lines, `FreeEdit`, `Obsidian`, `Settings`, `Advancement`). Every view is a template string assigned to `innerHTML` (158 sites), 56 inline `onclick=""` strings, manual `pushState` routing.
- `attachStepListeners()` is ~970 lines and re-binds every step's handlers on every render. `renderStep6` ~350 lines, `_lockBaselines` 244, `Chronicle._attachFormListeners` 414, `Sheet.render` 374.
- Freebie arithmetic exists in three parallel implementations plus a fourth in `getStepIncomplete`; `calcFreebieBreakdown` (7268) ignores `areteBonus` while `calcFreebies` (7314) subtracts it, so tooltip and total can disagree for chronicle-bonus characters. The mortal flow duplicates the whole set again.
- `M20.CREATION` / `M20.FREEBIE_COSTS` exist in data.js but the code mostly hardcodes `[7,5,3]`, `[13,9,5]` and point costs as literals.
- A thin `API` wrapper covers only `/api/characters`; ~80 other raw `fetch` calls swallow server error bodies. Five copies of the same custom-content cache pattern.
- Dead code: `attachDotListeners`, `validateStep`, `_mortalFreebieBreakdown`, `_bonusDotDiscount`, `_bonusDotsForTrait`.
- Patch-script residue: the four `patch_*.py` scripts did blind string replacement. The core-stat handler (10985-11019) has two interleaved guard layers from two patches; `renderMFCards` is in string-concat style unlike the rest of the file; tooltip HTML is baked inline instead of living in data.js.
- Positives: no stray `console.log`, cache-busting `?v=` strings, `escHtml` helper exists, session store and timezone helpers are tidy.

## 5. Extracted data cleanliness

### `js/data.js` (live, hand-authored, clean of PDF artifacts)
- 32 top-level keys. Spheres 9 × 5 ranks, primary Abilities 11/11/11, Backgrounds 36, Merits 117, Flaws 140, Archetypes 34, Practices 27, Paradigms 25, Instruments 62. All verified fragments match the source text.
- **Duplicate id** `clear_sighted` (two different merits, lines 1966 and 1987). Any id lookup picks one silently.
- **Missing M20-core secondary abilities:** Jetpack, Torture (Skills), Lore (Knowledge). "Pharmacopoeia" vs book "Pharmacopeia/Poisons".
- `page` is int for M20 and string for other books (~363 strings), and 8 bare ints are actually other-book pages (3 mortal Backgrounds; merits at 341/346/350/353/358 match no book).
- `cost` is int or one of 30+ ad-hoc string forms (`'1-5'`, `'2, 4, or 6'`, `'5 or 10'`) across 57 records.
- 10 distinct optional-flag key-sets on Backgrounds; 21 secondaries lack `page`.
- Merits/Flaws (Appendix II pp. 642-648) and Archetypes (pp. 267-273) are not in the extracted text, so their completeness is unverified.

### `server/rotes-seed.json` (954 rotes, raw extraction)
- Schema uniform; 941 have a source page; sphere names canonical; all ranks within 1-5.
- **Descriptions hard-truncated at ~175 chars: 674 of 954 end mid-sentence**, 5 empty, 30 start mid-word from column bleed.
- **Technocratic sphere names dropped, not mapped:** Data / Dimensional Science / Primal Utility vanish from `sphere_minimums` (34 rotes, 13 left with no requirement at all).
- 13 garbage names (`'188'`, `'610'`, `'Magick'`, `'Drug)'`, `'DMSO ('`, …), 14 hyphen breaks, 4 bled citations, mixed curly/straight apostrophes.
- `spheres_parsed` / `sphere_minimums` are JSON strings inside JSON (double-encoded).

### `data/wonders.json` (449 wonders, raw extraction, dirtiest)
- Most descriptions run into the next entry's name (26 confirmed by exact trailing match, far more by the auditor's looser heuristic); only 19 end in terminal punctuation.
- 63 descriptions embed the running header "N Mystic Armory", often splitting a word; 6 start with it.
- 721 hyphen breaks across 328 records.
- 12 empty descriptions, 5 that are only a header; `Armor`, `Car`, `Weapons` are section headings captured as items; `Universal Suit` is 20,456 chars and swallowed the book index; 3 other entries >3,000 chars contain multiple wonders.
- No `type` field (Talisman/Device/Charm must be inferred); stat fields are strings-or-null with 58 non-integer values; two apostrophe spellings of the same source book.

## 6. Repo and deployment hygiene

- **No git repository.** No history, no way to diff a patch, no rollback.
- No tests, no linter, no lockfile on disk (`npm install --production`, deps have drifted: better-sqlite3 9.6.0 installed vs ^9.4.3 declared). Switch to a committed lockfile + `npm ci`.
- Dead files (~1.4 MB): `public/app.js`, `public/data.js`, `public/style.css`, `public/css/app.js`, `public/js/index.html`, `public/js/style.css`, `server/routes/index.js`, `server/routes/db.js`, `server/characters.js`, `server/rotes.js`. Confirmed unreferenced via the require graph and index.html.
- `app/public` is bind-mounted read-only, so frontend edits are live immediately; server edits need `docker compose build`. Image and disk currently match.
- Dockerfile `EXPOSE 3000` and its healthcheck target :3000; compose overrides to 8009. Container runs as root.
- `public/tarot` is 280 MB of PNGs, 29 of them over 5 MB. Convert to WebP/AVIF and resize.
- 70 MB rulebook PDF and 700 KB of pdftotext dumps sit in the project root (excluded from the image, but should not ship with the repo).
